01 / 问题

财经信息
散落在三个 App 里。

公告在交易所、行情在券商 App、日程在日历——用户要自己拼。Agent 大多只回"数字"，不闭环成可确认的行动。

P-01
信息孤岛
同一条"动力电池产能回升"散在新闻、行情、财报三处，用户手动关联，容易漏。
P-02
Agent 只出数字，不出行动
现有工具读完公告就停，不把它变成"该排的日程 / 该确认的事"，缺人在回路。
P-03
事实与判断混在一起
行情数字、来源、主观分析不分层，用户分不清哪些可信、哪些是猜测。
P-04
失败没有兜底
日程过期、操作被拒时，Agent 直接卡死，不提示重试。
02 / 方案

新闻驱动，一条意图链

以新闻为主场景（12 官方场景之一），财经 / 日程作为它的关联证据与行动。官方允许多场景联动统一参评。

STEP 01 · INTENT
📰
读懂要闻
Agent 读新闻简报，保留来源与时间，抽主题 tag 与关联股票号，标记未读。
STEP 02 · ACT
⚙️
牵出关联
点主题 / 股票号，牵出关联财经卡；Agent 从公告里提取关键日期，排进日历（待确认）。
STEP 03 · VERIFY
✅
留人确认
用户点"确认排入"翻转为已落实；拒绝 / 过期 → Agent 将重试。关键动作永远留给用户。
03 / 技术

确定性兜底，LLM 可换

没配模型也永远能跑；配了 LLM 出真卡；人在回路 + 失败处理是评分硬项。

A
Fallback
确定性模板兜底
没 LLM / 没网 / 超时 → 走规则模板，demo 永不崩，保证可复现。
B
LLM
模型可插拔
复用天文赛 starter 的 model_factory，OpenAI 兼容，DeepSeek/GLM/Kimi 皆可换。
C
Human-in-loop
人在回路
订阅、排日程、标记已读，关键动作全留用户确认，不擅自执行。
D
Fault
失败可重试
拒绝 / 过期不卡死，显示"Agent 将重试"+ 重试入口，回到待确认。

06 / 演示

3 段录屏，照脚本走

提交材料要"任务演示与复现证据"——这 3 段就是意图→执行→核验的完整闭环。

REC-1意图 · 读懂
打开要闻 → 点主题 tag / 关联股票号 → 牵出对应财经卡并高亮。
时长 ~30s
REC-2执行 · 确认
财经卡点日程 → 日历卡同步翻转已落实；点订阅 → 触发待确认提醒。
时长 ~45s
REC-3核验 · 失败
日历卡"拒绝/过期"→ Agent 将重试 → 重试回待确认；新闻"标记已读"。
时长 ~30s
REC-4Rinx 分享
在 Rinx 会话用"网页卡片"分享 URL，录一次接收者打开的过程。
时长 ~30s
